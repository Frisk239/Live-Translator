# 字幕稳定：冻前缀，藏尾巴

观众真窗：半句中文整行重译、意思乱跳，跟着读会累。偶发 ASR 听错可忽略。

上一版「原文可长、译文等定稿」能止闪，但靠译文看直播的人开口会空一截。下面这套对齐 Google 同传 / Chrome 直播字幕，更优。

---

## 别人怎么做

| 谁 | 做法 | 效果 |
| --- | --- | --- |
| Google 同传 | **mask-k**：半句先藏译文最后几个词（不稳的尾巴）。**偏向已上屏的字**，避免同样好的译法来回摇摆。 | 早出字，少擦除 |
| Chrome 直播字幕 | Wait-k + **Greedy Text Stabilization** 冻前缀 | 30s 英→法闪烁 25 次 → 4 次 |
| CHI 2023 | 不稳字幕加疲劳；按词对齐，语义没变就不动 | 少分心、少累 |
| 有的产品 | 原文走 partial，译文等 final | 最稳，译文晚 |

闪的是「已经读过的字被整行换成另一个意思」，不是「后面多出几个字」。

---

## 选定方案（比纯等定稿更好）

**冻前缀 + 藏尾巴**，定稿再允许改写换一次。

草稿每来一版新译文 `T`（本机 CT2）：

1. 和屏幕上已亮的 `S` 算最长公共前缀（按字）。
2. 能对上：只**追加**后面的字；最后 2 个汉字（或 2 个英文词）先不亮（mask-k）。句末定稿时把尾巴揭开。
3. 对不上（整句意思跳了，Concord→和谐返回）：**屏幕上的译文不动**，等定稿。看起来暂时像「译文还没跟上」，总好过整行改意思。

定稿：

- 先揭开尾巴，亮完整本机译。
- LLM 改写最多再换 **一次**，然后冻死。hold 1s（在飞最多 2s）不变。

原文：照样跟着 ASR 长。开头被识别改掉（Okay→O）只能跟着改，那是原文层。

```
开口    原文「So we are」     译文（空或已冻前缀）
半句    原文「So we are going to try this」  译文「所以我们要试试」…（尾巴藏着）
定稿    原文冻住              译文揭开 + 最多改写一次
```

**仅原文**：只有原文在长。
**仅译文**：同样冻前缀+藏尾巴，开口就能有中文，不会整行跳。这是相对「等定稿才出字」多出来的好处。
**本机 LLM 直译**：草稿期没有本机译，译文仍等定稿（或 LLM 半截按同样规则冻前缀）。

---

## 为什么不选另外两个

| 方案 | 为什么不是首选 |
| --- | --- |
| 整条只出定稿 | 最稳，开口空。靠译文的观众会以为没在听。 |
| 原文草稿 + 译文等定稿 | 能止闪，双语/仅译文开口偏慢。当冻前缀对不上时的**退路**（第 3 步已经包含）。 |
| 半句也 LLM | req/s 打爆，闪得更凶。 |
| 只冻前缀、不藏尾巴 | 尾巴正是最爱跳的部分（Google 的结论）。 |

CT2 半句经常整句重写，冻前缀会经常走「对不上就不动」——行为接近等定稿，这是保底，不是失败。一旦某次 CT2 是往外长的，观众就能早看到中文。

---

## 改哪里

| 位置 | 做 |
| --- | --- |
| 引擎或壳，草稿上屏前 | `stable_trans(shown, next) -> 冻前缀 + 去掉尾巴`。草稿 `on_draft` 的译文走它。 |
| 定稿 | 完整 CT2，再走现有改写调度。 |
| ADR 0003 | 草稿可长；**已上屏的译文前缀不得改**；尾巴可藏。 |

不改：切条、识别、hold/lookahead、词表、每个草稿打 LLM。

---

## 验收

真窗英/日各一条正片，双语：

- 草稿期中文**已亮的字不整行换意思**；可以在后面多出字。
- 定稿揭开尾巴；改写最多再变一次。
- 仅译文开口也有中文（或短暂空，但不要每 350ms 换意思）。
- pytest：公共前缀保留；对不上则保持旧译文；定稿是完整句。
