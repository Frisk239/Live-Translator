# 听译优化路线

给下一刀执行会话用。产品是**观众听译**：看别人的外语直播，把听到的话译成简体中文叠在字幕窗上。不是给主播往画面里叠字幕。

术语只跟 `CONTEXT.md`：观众、音源、原文、译文、草稿、定稿、字幕条、切条、控制面板、开听、本机听译、托管听译。

---

## 1. 现在站在哪

### 1.1 本机听译（第一形态）已通

壳 → 本机引擎 WS 已通。PCM 为 f32le / mono / 16k。事件只有草稿 / 定稿 / 提示。

识别：Silero VAD 32ms + SenseVoice-Small 离线整段重识别。
翻译保底：CTranslate2 int8（en→zh 直译，ja/ko 经 en 枢轴）。草稿贪心，定稿 beam=2。
切条：ADR 0002，32 字 / 6 秒硬顶，句末还要换气 ≥250ms。

### 1.2 门禁（8 素材 × 3 次，真实竞争环境）

红线：首草稿 P50≤1000ms / P95≤1500ms，首事件=草稿，句末→定稿 P50≤1500ms，无孤立词定稿，数字不丢。
质量：基础链过线；语义锚点 ≥2/3。

仍红、且**不再用本栈微优化去打**的两条：

| 红 | 观测 | 根因 | 本路线是否再打 |
| --- | --- | --- | --- |
| en 历史朗读首草稿 | P50 ≈1079–1110ms | SenseVoice 要约 1100ms 有声才稳定吐出两个英文词；译只要 ~50ms | 否。换识别或改口径后再说 |
| ja2 古典锚点 | 0/3 | 原文已是「ラ夜 / 幻想工程 / 突瞬」，不是「洛阳 / 玄宗 / 杜子春」 | 否。接受为已知极限 |

其余正片（ja / ko / ko2 / en2）红线与锚点当前为绿。压力变体只走稳健性门。

### 1.3 已做完、禁止回退

- 前缀翻译复用（同字幕条原文前缀延长，草稿只译后缀，定稿仍整句 beam）。
- 不成条不翻译；有声 ≥0.5s 后未熟文本才 150ms 重试（躲开开口 200–300ms 的「うん / なんか？」）。
- 成条门只计假名 / 谚文 / 汉字（堵住「맞だ.」）。
- 数词规范（韩/日含量级才转阿拉伯数字，接纳 ASCII 混排）。
- 定稿 LLM **不得**同步堵在重活线程里。堵住时 ja2 定稿从 8–9 条掉到 3 条，ASR 80%→63%，首定稿 22s，句末→定稿红。改为 CT2 先出定稿后已恢复。

### 1.4 已证伪、不要重做

- 阶段 2：VAD 驱动 / 开头加密到 200ms 轮询。ja/ko 首草稿变快，但 ko_fast 放出孤立定稿「맞だ.」。
- 英一流式 Zipformer 20M 与 2023-06-26 int8：两词比 SenseVoice 更晚（en 历史 2100ms vs 1718ms）。热路径未接。探针：`.build_mats/onset_zipformer_probe.py`。
- 同步等 LLM 再切条。
- ORT `allow_spinning=0` / `TRY_INCREMENTAL_KV=True`（当前导出）。
- 为 ja2 专名先下 ja-zh / ko-zh CT2（Helsinki 官方无这对；原文层已死）。

### 1.5 可选 LLM 的现状（有配置才走）

配置：APPDATA `com.livetranslator.desktop/llm.local.json`（不进 git）。
OpenAI chat 格式。草稿仍 CT2；定稿 CT2 立刻发给观众，LLM 在后台改写同一条。

**第 1 步已落地**（双槽预取/改写、前缀剥标点、每条只预取一次、`llm_covers≥0.6`、上过屏不回退）。回放 6/6 覆盖。默认 flash。

**真窗结论（en_speech.wav，2026-08-20）**：覆盖率调度不是观众看到的问题。`boss fight` 每条定稿都是 CT2「老大争斗」，改写请求全被下一条在 ~1s 内 abort；预取打在首草稿「So we.」上，盖不住整句。`3000 HP` 出生「3000赫普」，有时 ~1s 后才改成「生命值」。系统提示已有「游戏术语不硬译」，短字幕条上 LLM 来不及落地。

结构：不是词表能修的。近邻把 LLM 当译者，不展示 Marian 硬译。我们的改写在真窗里赢不了切条（预取打在过短草稿上，定稿改写被下一条 abort）。细则：`docs/游戏术语首显.md`。

## 2. 别人怎么用 LLM（对照，不是照抄）

近邻：SakiRinn/LiveCaptions-Translator（Win11 实时字幕 + 译）、TheDeathDragon/LiveTranslate（SenseVoice/Whisper + LLM）。

共同做法：

1. **采音 / 识别 与 翻译分队列**。新句取消旧请求。绝不堵采音。
2. **译的是当前这一句**（句末、或停住不动、或半句拖太久），不是把整段历史当一条。
3. **流式上屏**：先出第一个字，不等整句 7 秒。
4. **带上文**：最近 1–2 条原文+译文进 prompt。
5. **Prompt 纪律**：只出一句译文；按常识修 ASR；专名可保留；关掉 thinking（否则 token 耗在推理上，译文是空的）。

他们多数**没有** Marian 保底，LLM 就是译者。我们要保本机无网也能开听，所以 CT2 必须留下。

## 3. 原则（写进实现，不要靠自觉）

1. 没配 `llm.local.json`（或字段不全）= 行为与纯 CT2 完全一致。
2. LLM 失败 / 超时 / 空译文 / 复读 =  silently 留 CT2，不闪、不重试堵线程。
3. 重活线程（VAD → 识别 → CT2）里禁止 `urlopen` / 等 HTTP。
4. 同一时刻画面上只亮一条字幕条。LLM 只改**当前这条**的译文，不新开条、不堆历史。
5. 草稿继续 CT2（开口延迟是识别墙，LLM 更慢）。
6. 定稿时刻仍以 CT2 到达为准（句末→定稿门）。LLM 是改写，探针把「同原文连续两条定稿」合成一条：时刻取首条，译文取末条。
7. 换模型 / 下载体积必须先在本文件或会话里写明再下。

## 4. 路线分三步

### 第 1 步：让本机 LLM 真能盖上（下一刀）

**目标**：连续朗读时，多数定稿能被 LLM 改写；红线不回退；ja 锚点仍过。

**改什么**

| 项 | 做法 |
| --- | --- |
| 取消旧请求 | 同一字幕条只保留最新一次 LLM。新草稿/新原文作废未完成的旧请求（比「下一条才丢」更早丢过期预取）。 |
| 预取对齐 | 用「本条最新译完的」盖定稿，不要要求与定稿原文逐字相同。可接受：全文相等，或定稿原文以预取原文为前缀（识别只加了尾巴）。 |
| 流式出字 | `chat/completions` 开 `stream: true`。先把已生成的译文写回当前条（仍是定稿事件、同一原文），不要等 `finish`。总超时用配置里的 `timeout_s`（默认 8–20）。 |
| Prompt | 系统提示写明：只出一句简体中文；不要解释/原文/引号；按常识修明显 ASR 错；专名可保留习惯译法。可选附带上一字幕条的原文+译文（最多 2 条，切条后的上一**定稿**）。 |
| thinking | 请求里带上关推理的字段。对 zen / 多数兼容端先试 `enable_thinking: false`；若 400 再降级不带该字段。不要让空译文落到字幕上。 |
| 并发 | 后台线程或队列消费者。识别线程只投递 `(bar_seq, orig)`。 |

**不改**：SenseVoice、切条常数、草稿 CT2、控制面板 UI（配置继续用本地文件）。

**验收（有 `llm.local.json` 时）**

```
cd desktop
$env:PYTHONIOENCODING='utf-8'
# 用 Python 3.12（装了 sherpa-onnx / ctranslate2 的那个）
python tools/quality_probe.py --only ja,ja2 --runs 1 --skip-stage-timing
```

- ja：基础链过、锚点 ≥2/3、红线过（句末→定稿仍按 **CT2 首条定稿** 计时）。
- ja2：红线过；锚点允许仍红。报告里 raw 定稿数应明显大于 coalesced 条数（说明改写发生过），或 coalesced 译文不再是纯枢轴腔（「英文转至」类）。
- 人工看事件：同一 `orig` 先 CT2 再出现更顺的中文，且没有因 LLM 少切条、ASR 掉档。

再抽 `en --runs 1`：首草稿仍约 1.1s（允许红），定稿条数与无 LLM 时同量级。

**回退**：`TRY` 不成或红线回退，关预取/流式，回到「只在切条后后台改写」。不要删 CT2。

### 第 1.5 步：本机 LLM 直译（当前刀，先试效果）

控制面板三选一：本机（CT2）/ 本机 LLM / 托管。

**本机 LLM**：同一套采音、识别、切条；`to_chinese` 不走。草稿原文先上屏，译文等 LLM 流式。预取仍每条一次，等草稿够长（≥4 词）再发。没配接口不能开听。HTTP 仍不进重活线程。失败不回退 CT2。

改写调度见 `docs/改写调度.md`。真窗下一刀：字幕稳定，见 `docs/字幕稳定.md`（草稿只长原文，译文等定稿）。

**验收**：选本机 LLM 开听，`to_chinese` 不被调用； vitest / pytest / py_compile。真窗看译文是否整句顺。

### 第 2 步：队列与壳（体验，可另开一刀）

- 引擎侧固定「投递队列 + 单消费者」，新 `bar_seq` 取消旧 HTTP（能中断 stream 最好）。
- 壳：定稿先显示 CT2；随后同原文的定稿只换译文，不重置「定稿时刻」、不闪成草稿。
- 控制面板增加「选用 LLM」开关与三项（base url / model / key）。key 只写本机，不进 git。不配则不加载。
- 探针 `settle_seconds`：有 LLM 配置时已自动 ≥ `timeout_s + 2`，保持。

验收：真机开听一条日语素材，字幕条节奏跟纯 CT2 一样，译文在 1–3 秒内被改顺，不会卡住下一条。

### 第 3 步：托管听译（第二形态，不在本机堆大模型）

CONTEXT 已写：托管时观众电脑只抓音、出字幕；没有账号不能开托管听译。

那边再上：真流式识别、更大译模或托管 LLM。本机不为此下 7B，也不重开「英一流式 Zipformer」除非开口探针两词快过 SenseVoice。

en 首草稿若仍要过 1000ms：改门口径（业界报 TTFB / 停顿后再亮），或托管流式识别。本机离线整段打不过两词墙。

## 7. 明确不做（避免下一刀走偏）

- 草稿走 LLM。
- 同步等 LLM 再 `on_final` / 再 `take()`。
- 重开阶段 2 轮询或把 SenseVoice 拧成流式。
- 为 ja2 锚点换识别或下 NLLB（591MB、CC-BY-NC）——除非另开「识别」专题。
- 把本机听译改成必须联网。
- 控制面板做成主播向（往画面里叠字幕）。
- 靠加长系统提示修硬译（真窗已证伪：请求根本没落地）。
- 翻倍预取（端点 ~1.5 req/s 限流，覆盖率掉一半）。
- 同步等 LLM 再切条（堵识别，已证伪）。
- CT2 出口黑名单/游戏词表（不普适，ASR 变体也盖不全）。
- 给观众做可编辑术语表。
