# 托管听译（第一版）

## Problem Statement

观众在自己电脑上看外语直播时，本机听译要下载模型、吃这台机器的算力。有的机器偏弱，有的人不想在本机跑听译。他们需要把听译放到我们的机器上，自己电脑只抓音、出字幕，观感仍和现在的字幕窗一样。

## Solution

同一款 Windows 壳里，本机听译和托管听译并存。控制面板听译页用分段控件选本机或托管（默认露出，不是两个 tab）。点本机永不弹登录。点托管且未登录时，整页换成登录/注册（邮箱+密码+记住我）。登录只解锁托管服务。登录后壳把现有听译缝连到我们国内那一台机器（生产走反向代理上的 WSS/HTTPS，开发连本机明文）。音不落盘。同一账号同时只能开一路，后开的顶掉先开的；被顶的壳不再自动开回来。这台机器路数到上限或内存到线时，新的开听拒绝并说明，已开听的不受影响。听译与本机共用一份实现（切条、草稿、定稿）；托管服务另做账号、顶号、满员和多路调度。

## User Stories

1. As a 观众, I want 在控制面板用本机|托管分段选择听译跑在哪, so that 我知道这一次吃的是这台机器还是我们的机器
2. As a 观众, I want 没账号时仍能开本机听译, so that 第一形态不断
3. As a 观众, I want 未登录点托管时看到登录注册同一屏, so that 我能立刻开用托管
4. As a 观众, I want 用邮箱和密码注册, so that 我有账号去开托管
5. As a 观众, I want 用同一邮箱和密码登录, so that 我能回到已有账号
6. As a 观众, I want 勾选记住我, so that 下次开软件不用再输密码
7. As a 观众, I want 不勾记住我则关掉软件后掉登录, so that 这台电脑不长期留着我
8. As a 观众, I want 点 × 藏面板时仍保持登录, so that 藏面板不等于退出
9. As a 观众, I want 登录页不出现找回密码, so that 我不会点一个做不到的功能
10. As a 观众, I want 注册成功即登录并停在托管, so that 少一跳就能选音源开听
11. As a 观众, I want 邮箱已被占用时得到明确说明, so that 我改去登录而不是以为坏了
12. As a 观众, I want 密码错误时得到明确说明, so that 我知道是密码不对
13. As a 观众, I want 登录成功后看到音源、字幕模式和开听, so that 托管和本机开听步骤一样
14. As a 观众, I want 已登录时看到自己的邮箱, so that 我知道现在是谁
15. As a 观众, I want 点邮箱进入个人中心, so that 我能管理账号
16. As a 观众, I want 在个人中心改密码（旧密码+新密码）, so that 我能换口令且不必发信
17. As a 观众, I want 在个人中心退出登录, so that 这台电脑不再用我的账号
18. As a 观众, I want 开听途中不能把本机和托管互换, so that 不会在听的时候突然换后端
19. As a 观众, I want 只开托管时不下载本机模型, so that 第一次用托管不必等几百兆
20. As a 观众, I want 第一次改回本机再下载模型, so that 本机该下的时候才下
21. As a 观众, I want 托管开听时字幕窗、草稿、定稿、静默撤条和本机一样, so that 观感不换
22. As a 观众, I want 音源、字幕模式仍在这台电脑选, so that 抓谁的音、怎么看字仍是我的事
23. As a 观众, I want 真断网重试失败后托管停并看到说明, so that 我知道可以改本机或等网再开
24. As a 观众, I want 被顶号时停听、字幕撤掉并看到已在别处开听, so that 我不会对着空白字幕发呆
25. As a 观众, I want 被顶或断网时不要自动改开本机, so that 这台机器不会突然下模型、吃 CPU
26. As a 观众, I want 同一账号在第二台电脑开托管时把第一台挤掉, so that 一路账号只占一路听译
27. As a 观众, I want 选托管时译文 tab 仍在, so that 面板结构不跳
28. As a 观众, I want 点进译文 tab 时看到托管不用这边的改写, so that 我不把密钥理解成会送到服务器
29. As a 观众, I want 改回本机后译文 tab 的大模型改写仍可用, so that 本机增强不受托管影响
30. As a 观众, I want 托管先不收费、不限额, so that 看直播可以一直开着
31. As a 观众, I want 连接我们的机器时走加密, so that 正在听的音不在路上裸奔
32. As a 观众, I want 不能自己改服务器地址, so that 我不会连到别人的机器
33. As a 观众, I want 满员时开听失败并看到现在满了, so that 我不会对着转圈以为坏了
34. As a 观众, I want 被顶后不要自动再开听, so that 两台电脑不会对着顶
35. As a 观众, I want 计划内上线或短闪断时字幕顿一下后继续, so that 服务换进程我不掉听
36. As a 观众, I want 多台电脑可以同时登录同一账号, so that 第二台能进面板；只有开听才顶掉另一路
37. As a 观众, I want 改密码后其它电脑上的登录立刻失效, so that 旧钥匙不能再开托管
38. As a 观众, I want 试得太勤时看到暂拒说明而不是账号被锁, so that 我过一会儿还能再登

## Implementation Decisions

- 同一壳并存；听译方式用分段控件（本机 | 托管），不是两个 tab、也不是音源那种单选行。听译 / 译文两个 tab 保持原样。分段默认露出。
- 未登录点托管：控制面板整页换成登录提示（分段控件仍在）。登录成功后同一页露出音源、字幕偏好、开听。本机永不弹登录。
- 账号：邮箱标识，密码哈希存账号库——单机默认内嵌 SQLite（`server/hosted.sqlite3`），配 `LIVE_TRANSLATOR_DB_DSN` 走 Postgres（ADR 0032）。不发信、不验证邮箱、不找回。登录和注册同一屏。记住我才跨次留下登录会话（token 进系统凭据库，不进 `settings.json`）；不勾则进程退出即掉。多台可以同时登录；顶号只卡开听。同一来源短时间登录失败太多次则暂拒，不锁账号。
- 个人中心：点邮箱进入。第一版只有改密码；账单等以后再出现，不预留「即将上线」空位。改密码作废其它登录态，本机换新 token 仍保持登录。其它电脑若正在开听：停听并说明要重新登录，不自动再开。
- 壳 ↔ 听译仍是现有 WebSocket 缝：文本帧 `start` / `switch` / `stop`，PCM 为 f32le / mono / 16kHz 二进制帧；回 `draft` / `final` / `notice`。托管只换对端（安装包写死生产源，开发用环境变量盖成 `127.0.0.1` 明文）。
- 托管听译缝握手必须带登录 token（优先第一条文本帧）。不对就关，不收 PCM。顶号和满员在这一刻判定。本机听译缝仍只绑回环、不鉴权。
- 提示种类在现有 `notice` 上增加：被顶、网断、满员、登录失效。静默撤条、切条挤压仍是壳的规则；切条仍是听译的规则。
- 新缝：壳 ↔ 账号的 HTTPS JSON（注册、登录、退出、改密码、会话）。听译 WebSocket 不把密码放进听译缝。
- 顶号：同一账号同时一路托管。后开成功则先开的那路收到被顶提示并停听、撤条，不再自动开回来。
- 满员：部署时可配的并发路数上限 + 内存到线硬拒。新开听失败并说明「现在满了」。不排队、不降质、不挤别人。不用 CPU/load 当开听闸。启动按核数给保守默认；真正的 N 在目标机器上用多路 PCM 压测（红线：开口延迟、RSS）后写入配置。
- 已接入的多路共用一份模型；识别/翻译进有界线程池（同时跑的路数按核数配置，个位数），其余排队。第一版不做 SenseVoice 批处理。
- 音不落盘、不写字幕历史。听译上下文只在这次开听的内存里。账号、登录会话、在听会话进账号库：单机默认 SQLite，多机时给两台配同一个 Postgres DSN 认同一批账号和在听（ADR 0018 / 0032）。
- 托管服务第一版一个 OS 进程、两模块（账号、听译调度），听译引擎可换。一台国内机器。生产 TLS 由反向代理终结，进程只听本机。不为此上 GPU。不加机器、不拆两个 OS 进程；以后加机器靠 Postgres 认同一批账号和在听，满员仍是每台自己的闸。
- 计划内上线：进程收到退出信号后停接新路（与满员同一句说明），已有在听继续直到结束或可配超时，然后退出。起来时清无人认领的在听行。仍开着的壳用同一登录和音源再开一路（闪断）。崩溃走同一条重连；重试失败才提示停听。不切本机。不续同一条缝上的 PCM。
- 在听缝空闲超时：一段时间既无 PCM 也无文本帧，视为断开，清在听、放名额，按网断处理（可再开）。不开单独心跳。
- 共用听译抽到仓库单独一层，本机 sidecar 和托管服务都引用。本机仍单路，字幕行为与现有测试不变。满员、顶号、再开听、线程池只存在托管服务进程。
- 只选托管且未用过本机：不下本机模型。
- 托管不用观众在译文 tab 配的大模型；密钥不上我们的机器。
- 先不收费、不限额。以后账单挂在账号上，若记用量只记开听起止，不记音和字。

## Testing Decisions

- 只测对外行为，不测哈希算法、进程内部缓冲、GPU/CPU 线程数、线程池实现。
- 听译缝：沿用现有假听译 / 真听译缝测试。共用听译层必须通过同一套草稿、定稿、提示时间轴；另测被顶、网断、满员三条 `notice`。抽取后本机听译原测试仍绿。
- 账号缝：打 HTTPS JSON。覆盖注册、登录、重复邮箱、错密码、记住我 / 不记住、改密码、未登录不能开托管缝、握手 token 不对则开不了听译缝。
- 壳：分段切换、未登录点托管出登录页、登录后露出开听、点邮箱进个人中心、选托管时译文 tab 的说明、被顶不自动再开、闪断再开、真断网失败不自动切本机。可用假账号服务，不必真连生产机器。
- 满员和路数 N：压测脚本在目标机器上扫并发，写出配置；不把「30」写进断言。

## Out of Scope

短信、邮件、魔法链接、邮箱确认、找回密码、收费和额度、字幕/音历史、个人中心里的账单、托管侧大模型改写、GPU、多机分配/负载均衡、双机热切、两个 OS 进程、观众可改的服务器地址、满员排队、降质接入、用 CPU 健康分当开听闸、开听途中切换本机/托管、C++/Rust 听译运行时、SenseVoice 批处理、流式识别下一跳、单独的维护管理口、登录互斥（同时只能一台设备登录）。
