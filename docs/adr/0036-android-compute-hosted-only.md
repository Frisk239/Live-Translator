# 安卓端算力全在托管侧，端上不跑听译模型

安卓端只做托管听译（spec v2 与 `chanpin/android/prototype` 已定），本 ADR 补上调研证据并把它定为不可谈判项：手机端**不提供任何「本机听译」档位、不内置识别/翻译模型**，端上仅保留 VAD/能量检测这类小计算（「这个 App 不让抓」的静音提示）。

证据（docs/research/android-on-device-vs-cloud.md）：业界没有「识别+翻译」双模型实时同传的端侧产品——Google 的带翻译产品选云端，端侧的 Live Caption/小米华为 AI 字幕全是单 ASR、系统级特权、专用小模型且砍老机型（小米因老机型发热下架）；第三方路径上通用模型（whisper base RTF≈1.82 @骁龙662、流式慢 5×至 ANR）不可行，能实时的只有 30–80MB 英语流式小模型（Vosk WER 9.85% 档），译文质量够不到产品线。持续一小时级的直播场景同时放大性能与发热两个问题（用户拍板的判断与实证一致）。

模拟器端到端已实测闭环（安卓抓音→推流→托管识别翻译→字幕回显），端侧零听译算力不影响链路成立。换向条件：无——除非产品另立「离线无翻译」形态，那是另一个产品。
